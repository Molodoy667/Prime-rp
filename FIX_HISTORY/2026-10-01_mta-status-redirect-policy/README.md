# FIX: Политика редиректов проверки статуса MTA

Дата

2026-10-01

Статус

TESTING

## Проблема

В тесте и контракте мониторинга ожидалась ручная обработка HTTP-редиректов, но fetch-вызовы не передавали `redirect: 'manual'`. Клиент при этом показывает `—`, когда сервер не подтверждён мастер-листом.

## Установленная причина

В `worker/status.mjs` отсутствовал явный параметр политики редиректов. Отдельно подтверждено, что текущий сервер `94.23.168.153:22097` помечается мастер-листом как `offline`, а прямое TCP-подключение к порту с внешней среды не проходит.

## Цепочка

`/api/server-status` → `loadStatus()` → `master.mtasa.com/ase/mta/` → `parseMasterList()` → ответ со статусом сервера → клиентский валидатор `src/data/api.ts`.

## Изменённые файлы

- `worker/status.mjs` — добавлен `redirect: 'manual'` для основного и резервного запросов к мастер-листу.

## Исследованные, но не изменённые

- `api/server-status.js` — проксирует результат `loadStatus()`.
- `api/launcher.js` — отдельный API лаунчера; не менялся в последнем commit.
- `src/data/api.ts` — корректно требует числовые онлайн/лимит только для статуса `online`.
- `tests/server-status.test.mjs` — зафиксировал ожидаемую политику редиректов.

## Проверка

- Проверен опубликованный и локальный flow статуса.
- Прямой запрос к мастер-листу вернул актуальную запись с `notResponding=true` для целевого сервера.
- TCP-проверка `94.23.168.153:22097` извне не прошла.
- После правки повторно запущены серверные тесты.

## Ограничение

Этот фикс не открывает игровой порт и не может сделать сервер онлайн без доступности MTA-порта на хостинге.
