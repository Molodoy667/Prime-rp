# FIX: Перенесення форуму в базу та адмінська модерація

Дата: 2026-09-30

Статус: TESTING

## Проблема

Форум використовував демо-масиви та `localStorage` для тем, відповідей і розділів. Через це контент не был гарантированно доступен на сервері. API підтримував тільки створення теми й відповіді. В адмінці не було збереження тегів користувачів або перенесення тем між розділами.

## Коренева причина

Джерелом стану інтерфейсу були `seedCategories`, `seedTopics`, `seedReplies` і локальні записи браузера; повної схеми таблиць і серверних операцій для форуму в проєкті не було.

## Як працює система

Інтерфейс `src/components/Forum/index.tsx` викликає `/api/forum` або `/api/forum-auth` → API отримує MySQL pool через `api/_db.js` → `api/forum-schema.js` перевіряє/створює таблиці → дія перевіряє користувача та роль у `forum_users` → дані записуються в `forum_categories`, `forum_topics`, `forum_replies` або `forum_users` → API повертає актуальний стан, яким оновлюється інтерфейс.

## Досліджені файли

- `api/forum.js` — поточні GET/POST операції та SQL-запити.
- `api/forum-auth.js` — реєстрація, авторизація й payload профілю.
- `api/_db.js` — підключення MySQL.
- `src/components/Forum/index.tsx` — UI, локальні demo fallback-и та обробники дій.
- `src/data/forum.ts` — типи та seed/demo-контент.
- `src/styles/global.css` — стилі форуму й адмінських компонентів.

## Змінені файли

- `api/forum-schema.js` — новий schema/upgrade шар: створює таблиці форуму, додає відсутні колонки та первинні розділи.
- `api/forum.js` — повний CRUD для розділів, тем і відповідей, модерація, перенесення тем, профілі та теги; права перевіряються за роллю в БД.
- `api/forum-auth.js` — ініціалізація схеми та повернення профілю/тегу з БД.
- `src/data/forum.ts` — залишені типи й session storage; демо-контент видалений.
- `src/components/Forum/index.tsx` — завантаження тільки з API, серверне збереження всіх дій, панелі перенесення тем і редагування тегів.
- `src/styles/global.css` — стилі тегів і адмінських списків.

## Досліджені, але не змінені

- `api/_db.js` — підключення вже централізоване й відповідає API.
- Інші API сайту — не беруть участі у форумному flow.

## Backup

Оригінальні версії змінених файлів збережені в `backup/`. Для нового `api/forum-schema.js` оригіналу не існувало.

## Fixed

Підсумкові версії збережені в `fixed/` з тією ж структурою шляхів.

## Що конкретно виправлено

- Прибрано джерело контенту з demo seed-масивів і локальних копій браузера.
- Додано `forum_users`, `forum_categories`, `forum_topics`, `forum_replies` з upgrade-перевіркою для вже існуючих таблиць.
- Додано збереження/редагування/видалення тем і відповідей, розділів, профілю, pin/lock та переміщення тем.
- Додано `tag_label` і `tag_color`, серверну перевірку адміністратора та UI для зміни тегів кожному користувачу.
- Додано безпечне читання JSON-тегів і відсутність довіри до ролі, переданої клієнтом.

## Чому обрано цей fix

Причина була підтверджена прямим читанням frontend та API: локальні seed-и ініціалізували стан, а більшість обробників змінювали лише React state. Тому мінімальний коректний fix — перенести source of truth у MySQL і залишити `localStorage` тільки для сесії браузера.

## Ризики

На першому запиті до API схема може виконати кілька `CREATE/ALTER` операцій, тому користувач MySQL має права на структуру таблиць. Видалення розділу залишає його теми без категорії, а не видаляє теми. Розрахунок онлайн-статистики як і раніше залежить від наявності `ugta_players`.

## Перевірка

- `npm run build:vercel` — успішно; TypeScript і production bundle зібрані.
- `node --check api/forum.js` — успішно.
- `node --check api/forum-auth.js` — успішно.
- `node --check api/forum-schema.js` — успішно.
- `git diff --check` — помилок пробілів не виявлено.
- Реальний запит до MySQL, реєстрація, створення теми/відповіді та перевірка адмінки в браузері — не виконані: у поточному середовищі немає підключених production DB variables.

## Результат

Код готовий до перевірки на сервері з актуальними DB variables. Статус залишено `TESTING`, оскільки віддалене виконання SQL і browser E2E не підтверджені.

## Rollback

Повернути тільки змінені робочі файли відповідними копіями з `backup/`. `api/forum-schema.js` є новим файлом; його видалення під час rollback має виконуватися лише після перевірки, що жоден API більше його не імпортує.
